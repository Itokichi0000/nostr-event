# 設計判断の記録

PRD に明記がない細部について、安全で単純な案を選んだ記録。鍵・個人情報・金銭に関わる変更は行っていない。

| # | 判断 | 理由 |
|---|---|---|
| 1 | パッケージマネージャーは **pnpm**、TypeScript は 5.9 系に固定 | 新規プロジェクトのため（CLAUDE.md）。TypeScript 7 はネイティブ版で Next.js の対応が未確認のため見送り |
| 2 | shadcn/ui は CLI を使わず、同じ方式（cva + tailwind-merge）で必要な部品だけ `components/ui` に実装 | 外部レジストリに依存せず再現可能にするため |
| 3 | 署名が必要な API は「署名なしで呼ぶ → 428 + サーバーが組み立てた雛形 → 署名して再送」の2段階 | 公開内容の雛形を DB からサーバーだけが組み立て、署名内容をタグ単位で完全一致検証できる |
| 4 | 公開イベントの `status` は、1リレー以上の `OK true` を確認するまで `publishing`（一覧・申込は不可） | PRD 4.2「ACK確認後に published」。全失敗時は `failed` と主催者通知、管理画面から再送 |
| 5 | 単日の終日イベント（31922）は `end` を省略。複数日は排他終了日を付ける | NIP-52 で単日は省略可。クライアント間の解釈差を減らす |
| 6 | 公開 RSVP の `d` は `sha256("gather-rsvp:" + 申込ID)` の先頭32桁 | 署名前後・取消（declined）で必ず同じ値になり、申込IDそのものは公開しない |
| 7 | 置換可能イベントの雛形 `created_at` は常に「前の版 + 1秒」以上 | 同じ秒に2版を署名するとリレーが古い方を残す場合があるため（テストで再現して修正） |
| 8 | ゲストの再送（同じ idempotency key）は、初回から15分以内に限り新しいチケットを発行して旧チケットを失効 | 応答を受け取れなかった再送で二重申込させずにチケットを渡すため。キーはクライアントが生成し sessionStorage にのみ保持 |
| 9 | Nostr 参加者の「チケットを表示」は毎回新しいトークンを発行（旧QRは失効） | DB にはハッシュのみ保存するため。PRD 6.2 の方針どおり |
| 10 | 失効したチケットのハッシュを `revoked_tickets` に残す | 受付で「古いQRです」と「無効なQR」を区別して案内するため |
| 11 | 申込受付はイベント開始時刻まで。受付は開始2時間前〜終了2時間後（列で上書き可） | PRD 7.2 のデフォルト |
| 12 | 定員を増やした／無制限にしたときはキャンセル待ちを自動で繰り上げ。確定者数未満への減少は禁止 | PRD 13（V1 は変更禁止）。繰り上げはキャンセル時と同じ処理 |
| 13 | NIP-46 の通信用一時鍵（利用者の nsec ではない）は **sessionStorage** に保持 | タブを閉じれば消える。再接続の手間より漏えい範囲の小ささを優先 |
| 14 | 外部 RSVP の通知は「意思表示が変わったときだけ」、dedupe key は Nostr イベント ID | 同一人物が別 `d` で何度出しても通知が増えない |
| 15 | 外部クライアントによる主催者本人の更新は、タイトル・日時・場所・説明・画像・タグのみ反映 | 定員・承認方式などアプリ固有設定は上書きしない（PRD 4.2） |
| 16 | 画像は開発時ローカルディスク（`UPLOAD_DIR`）。先頭バイトで PNG/JPEG/WebP/GIF を判定し SVG は拒否 | S3 互換ストレージは `lib/storage/images.ts` の差し替えで対応予定 |
| 17 | レート制限は PostgreSQL の固定ウィンドウ。IP はハッシュ化して保存 | 初期版で Redis を必須にしない（PRD 10） |
| 18 | ワーカーのリレー監視は30秒ごとに対象を再計算し、約5分ごとに購読を張り直す（再接続を兼ねる）。カーソルは EOSE 後に更新し、再起動時は10分重ねてバックフィル | 取りこぼしより重複の方が安全（重複は id 主キーで排除） |
| 19 | E2E では NIP-07 の `window.nostr` をテスト側から注入（秘密鍵は Node プロセス内のみ） | 実署名器なしで作成〜受付の主要フローを検証するため |
| 20 | iOS/Android/PC の Web Push は「ベストエフォート」と画面で明示。通知履歴は常にアプリ内に残す | PRD 9.2 / 9.3 |
| 21 | `app/loading.tsx` は置かない | ルートに置くとストリーミングが先に始まり、存在しないイベントでも HTTP 404 にならないため |
